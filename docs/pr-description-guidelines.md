# PR description guidelines

Fill in the [PR template](../.github/PULL_REQUEST_TEMPLATE.md). The sections below
clarify how to use it well.

## What this PR does

Describe the motivation — *why* this change is needed (e.g. "to keep the
documentation accurate", "to fix a regression in …") — and *what* was
changed, as a concise summary or bullet list.

## Why we need it and why it was done in this way

Explain tradeoffs and alternatives considered. Do not repeat what the code
already shows.

## Checklist

The checklist is not enforcing, but fill it in honestly: mark items `N/A`
explicitly rather than leaving them unchecked, and keep routine/procedural
items terse (e.g. a plain acknowledgment for "AI Contributions" is enough; see
[docs/commit-message-guidelines.md](commit-message-guidelines.md) for what the
AI-assistance disclosure itself requires). Add detail only where it's
substantive, such as a real design tradeoff or a genuine reviewer heads-up.

## Release note

Use `NONE` for docs-only or internal changes with no user-visible effect.
Otherwise, describe the user-visible change and any required user action.
